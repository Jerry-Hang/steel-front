## 2. 本会话干了什么（用户任务：CPU 瓶颈拆分 + 浮点 SIMD 扩展）
- 亲和线程池（`src/engine/cpu.rs`，勿回退）：
  - `cpu::topology()` 全局 `OnceLock` 缓存，Game/Renderer 复用一次探测
  - `scene_compute_set()`=首簇（AMD CCD0 / Intel 仅 P-core）；`ai_set()`=AMD CCD1 /
    Intel E-core≥8 用 E-core 否则 P-core（用户调度策略落地）
  - `ThreadPool::par_for_each_mut(data, f)`：持久亲和池，`f(seg_idx, global_start, seg_slice)`，
    调用线程参与首段，join 后才返回；`SendPtr<T>` 裸指针擦除 → 元素/闭包无需 `'static`；
    spawn 失败自动补计不死等；`RV3D_SCENE_WORKERS`/`RV3D_AI_WORKERS` 调线程数（默认 min(8, 集合)）
  - 渲染线程不固定 1-2 核：主线程与 scene_pool 同绑整簇集合，OS 调度器在集合内选空闲核
- 并行剔除/上传（`renderer.rs::cull_and_upload`，勿回退）：两阶段——
  阶段 A 段并行剔除（SIMD 选路 AVX-512>AVX2>AVX>SSE4.2>NEON>标量，逐位一致）写
  `culled_scratch` + 段计数（AtomicU32）；前缀和（串行，段数≤9）；阶段 B 段并行压缩上传
  （近档在前、远档随后）。`visible/near/far` 语义与冒烟断言不变

## 3. 实测数据（本会话，权威）
| 指标（2560×1600+64v64+基准钩子 pitch=-10） | 改动前 | 改动后 |
|---|---|---|
| fps p50 | 42 | **99.2**（2.36×） |
| CPU 单核峰值 | 86–94% | **~47%** |
| cycle_us p50 | 13620 | 10155 |

- 1280×800 同条件：fps p50 194→298；GPU util ~30%、功耗 ~24W、显存 2.47GB 不变
- **诚实结论**：爆炸冲击波 AVX-512 ≈ 1.0×（`[f32;3]` AoS+gather 是内存/取数瓶颈非计算瓶颈）；
  AVX-512 真实收益在计算密集路径（剔除 16 实例/批、地形 morph）。若日后做真爆炸系统，用 SoA 布局
- 剩余瓶颈：`present_us`（dzn/WSLg 转译层固有，MAILBOX/IMMEDIATE 无差异）→ 唯一根治路径是
  Windows 原生 Vulkan；GPU util 30% 同源，非 CPU 代码问题
