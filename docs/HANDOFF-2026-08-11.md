> 本交接面向**下一个接手输入/鼠标捕获的 AI 会话**。核心：WSLg/Xwayland 的鼠标捕获

## 一、用户诉求（原话要点）

1. 期望 CS2 式鼠标捕获：进入游戏鼠标消失、被窗口捕获、移动鼠标 = 转动视野。
2. 当前实际表现（2026-08-11 用户实测）：
   - **新开局（StartMenu→Playing）视角冻结**：鼠标移不动视角（"捕获不了鼠标"）。
   - **死一次后按 R 重开，鼠标才"有效"**：变成 Minecraft 式——指针位置 = 准星位置，
     移动鼠标 = 准星跟着移动（可接受），但**鼠标图标一直悬浮在窗口上不消失**。
3. 用户已明确：**本轮不要再改代码**，写交接文档收尾（本文件 + AGENTS.md）。

## 二、环境铁律（已实测，勿回退/勿重走）

- 本机 = WSL2 + WSLg/Xwayland，`DISPLAY=:0`；游戏强制 X11（`with_x11()`）。
- **真实物理鼠标只产生 CursorMoved（绝对位置），不产生 XI_RawMotion（raw 相对）**：
  用户会话实测开局 55 秒内 `cam: yaw` 仅 0.0→0.1°、`pitch` 0.0→-0.2°（视角冻结）。
  冒烟脚本用 `XTestFakeRelativeMotionEvent` 注入时有 raw 事件——**勿用冒烟结果反推真实鼠标**。
- `set_cursor_grab(Locked)` 在 WSLg 返回 Err；`Confined` 返回 Ok 但**实际不真正 confine**
  （指针仍可漂出窗口，漂出后窗口收不到 CursorMoved → 视角冻结）。
- `set_cursor_visible(false)` 在 Xwayland **不隐藏鼠标图标**（用户实测图标一直悬浮）。
- `/dev/input/` 与 `/dev/uinput` 在 WSL2 不存在 → **rdev 库在此环境监听/模拟均不可用**，
  已向用户说明；等 Windows 原生 Vulkan 再评估 rdev。
- 内存 12GB，一次只跑一个 cargo；`cargo test` 需提权（UDP 回环沙箱 bind 被拦）。

## 三、代码现状（2026-08-11 三次修订后，已推送）

- 双路径（`src/main.rs`）：
  - `cursor_locked`（Locked grab 成功）→ `DeviceEvent::MouseMotion` raw 相对驱动；
    捕获瞬间一次回中 + 150ms 吞回声 + `MAX_RAW_LOOK_DELTA=1024` 守卫。
  - `cursor_locked=false`（WSLg）→ 绝对位置路径：基准 = 真实指针位置，
    **只有 `set_cursor_position(...).is_ok()` 才把基准设为窗口中心**（修复 868d127 的
    "warp 失败仍把基准设中心 → 灵敏度爆炸/压地" bug）；首个 CursorMoved 作基准
    （`abs_baseline_valid`）；512px 传送守卫只跳服务端跳变。
- `sync_cursor()` 每帧调用（`update()` 开头）：`want = focused && Playing && !settings_open`。
- 冒烟脚本（`scripts/gameplay_smoke.py`）已修：从 `~/.steel_front.cfg` 读真实灵敏度
  （`0.0005 + s*0.002`），分块注入（≤400px/事件，兼容 512px 守卫）。

## 四、本轮实测证据（用户会话 /tmp/play_run.log）

```
10:06:03 game: run started (wave 1)
10:06:03 input: cursor captured (mouse look on, grab=confined, look=absolute)  <- 开局即登记捕获
10:06:03..10:06:58  cam: yaw 0.0→0.1, pitch 0.0→-0.2                        <- 视角冻结
10:06:58 input: cursor released
10:07:01 input: cursor captured ...
10:07:14 game: player down ... GameOver
10:07:16 game: run started (wave 1)                                          <- R 重开
10:07:16 input: cursor captured (grab=confined, look=absolute)               <- 此后用户说鼠标"有效"
```

**解读**：开局捕获已登记（grab=confined 返回 Ok），但 confine 实际不生效 → 可见指针
漂出窗口 → 窗口收不到 CursorMoved → 视角冻结。死亡重开后用户指针恰在窗口内移动 →
事件恢复 → Minecraft 式瞄准。**根因不是"没进入捕获态"，而是指针没被真正 confine +
鼠标图标没被隐藏。**

## 五、下一个 Agent 的修复假设（按优先级）

- **H1（最可能，先做）**：WSLg 无法真正 confine 指针 → 需要**每帧把指针拉回窗口内**
  才能持续收到 CursorMoved。已有"每事件 warp 回中心 + is_ok 检查"逻辑，但 warp 在
  Xwayland 上可能失败（返回 Err 或静默无效）。验证/修复方向：
  1. 加诊断日志：`set_cursor_grab(Confined)` 返回值、`set_cursor_position` 返回值、
     `Focused` 事件、每帧收到 CursorMoved 计数（前 60 帧打一次）。
  2. 若 warp 无效：改用 x11rb（已在 winit 依赖树，Cargo.lock 已有，加直接依赖不新增
     第三方下载）对窗口执行 XWarpPointer，或 XTest 注入回中。
  3. 备选：接受 Minecraft 式（指针=准星）——把 HUD 自绘准星改成跟随指针位置
     （或隐藏自绘准星），并把"指针漂出窗口"问题用 warp 保持解决。
- **H2**：`focused` 依赖存疑——开局 `focused: true` 初始化，但 WSLg 焦点模型可能发
  `Focused(false)` 后再无 FocusIn。建议日志记录；若确认，`want` 条件改为
  `(focused || 窗口处于指针下)` 或干脆去掉 focused 依赖（X 的 motion/button 事件
  不受焦点约束，键盘事件才需要焦点——WASD 之前可用说明焦点问题不大）。
- **H3**：隐藏鼠标图标——`set_cursor_visible(false)` 在 Xwayland 无效 → 用
  `XDefineCursor(win, 空光标)`（x11rb）强制隐藏；或 winit `set_cursor(自定义透明
  cursor)`。验证方式：捕获后截图/xprop 查窗口 cursor。
