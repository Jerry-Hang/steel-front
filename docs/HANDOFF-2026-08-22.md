## 一、枪械检视模式与 AK-12M 重建

**做了什么**
- 新增枪械检视模式（`--inspect=N` / `RV3D_INSPECT=N`，N=1-35）：进入后只渲染枪模，
  Orbit 相机拖拽旋转 + 滚轮缩放，用于建模反馈（`3af9dfe`）。
- 检视环境改为**白色虚空**（`e01ef8b`、语义 `renderer.void_mode` → 无地形/NPC/标记，
  清屏底色纯白），便于与透视/夹具对比。
- 重建 **AK-12M** 模型（`b716870`），并做产品级构图收尾（`20f8cf2`）：自定义深色枪口
  组件 + 补齐护木与导轨之间的缝隙、用长焦（小 FOV）取景消除极端透视畸变。

**关键决策**
- 检视模式是**独立路线**：不进 Playing / FirstPerson，不触发正常战斗逻辑，仅服务建模评审；
  枪模仍走专属烘焙光照路径（flat=3，2026-08-22 marker 改实时光照后枪模保持烘焙）。
- 用「白色虚空 + 长焦」代替默认第一人称持枪视角来评审枪模——前者能暴露单边透视畸变与
  部件缝隙，后者容易把透视当成造型问题。

**验证结果**
- 检视下枪模几何完整：护木-导轨缝隙被补齐，枪口组件不再显得庞大突兀；
- 长焦取景后近端畸变显著收敛，AK-12M 三视图/斜 45° 构图可用；
- 后续发现**检视模式的 FP 枪模在结算态会漂浮在世界中**，已用 `056bc1f` 修复为仅在
  Playing+FirstPerson 渲染。

## 二、手绘城市地图取代随机种子

**做了什么**
- 新增 `src/engine/city.rs`，以**手工绘制的现代城市布局**（`5853650`）取代确定性随机
  种子生成；`game.rs` 默认 `map = city::generate_city()`（`RV3D_PROC_MAP=1` 可回退程序化
  生成用于 A/B）。
- 街道网格 55m（`STREET_EVERY`），主街中心线位于 k×55m；街区在中央广场（纪念碑）/ 写字楼群 /
  仓库园区 / 公园树阵 / 商铺街 / 军事哨卡 / 停车场残骸之间铺开；街道含双向主街 + 路灯 +
  消防栓 + 中央隔离路障 + 人行道；边界为混凝土围墙 + 4 座大门。
- 障碍改为真高楼（不再是 2.4m 平板），按半高/中心高/材质 tint 建模：建筑有高度关系、
  消防栓红 / 树冠绿 / 玻璃幕墙蓝灰等专属色；标记（marker）恒为 3D 立方体（修复远处
  quad 拉方）。

**关键决策**
- 城市**布局手工绘制**而非随机：让街区/建筑/遮挡有结构、可设计（掩体与狙击走廊可控），
  代价是布局代码更长但这正是要的形状。随机种子只保留在颜色/地面纹理噪声里。
- 地面纹理与布局**同源**：`procedural::generate_city_ground_texture`（1024）与
  `city::ground_zone` 共享街道/街区常量，避免「地图是城市、贴图却是荒地」的错位。

**验证结果**
- 城市地面纹理 1024 上街/人行道/广场/地基/草地沙土分域清晰（含黄中线、路缘磨损条、
  人行道 2m 分缝、广场 4m 分缝），加上 AO + 烘焙光照，**去方块贴图感**明显改善；
- 障碍由 2.4m 平板变为真正高楼，视野里有高低错落与遮挡；天空清屏为蓝，不再土黄。

## 三、障碍物立体化（实时光照 / 混凝土砌块皮肤 / 树冠错落）

**做了什么**
- 障碍/NPC 从「平面剪影」改为**实时 Blinn-Phong 光照**（`266aade`）：法线光照 + 高光，
  告别纸片感；同时提亮日光（环境光 0.5、太阳 1.5）。
- 加**混凝土砌块墙面纹理**（`409fd0d`，自动开启）：逐面光照 + 保色混合 0.45，墙体带
  表面细节，6 面读起来像 3D 盒子。
- 公园树冠**逐棵大小/高度变化**（`056bc1f`），打破「整排绿色墙」的呆板感。

**关键决策**
- 障碍/NPC 走实时光照（flat=0），枪模仍走专属烘焙路径（flat=3）；两者共享 instance buffer，
  用 `flat_flag` 在片元里分流——新增功能一律走 mesh 路径，传统顶点管线保持冻结。
- **阴影图默认关闭**：待高楼城市的阴影覆盖修复（当前高楼容易让阴影图大面积空白/穿帮），
  先保正确性与帧率；`RV3D_NO_SHADOW` 语义相应弱化。

**验证结果**
- 障碍表面有明暗与高光，墙体现「砖块/砌块」纹理 + 逐面光照 = 立体盒子而非扁片；
- 树冠按棵随机大小/高度后，公园由「绿墙」变为有层次感的树阵；
- 实时光照后 marker/NPC 仍是着色器内 tint×纹理混合（皮肤纹理默认开启，`RV3D_SKIN_TEX=0`
  关闭回退纯色）。

## 四、真实音频输出（waveOut 环形缓冲）

**做了什么**
- 新增 `src/audio_out.rs`（未提交）：winmm `waveOut` 直接 FFI 的 `WaveOutSink`，
  16-bit PCM 交错样本 → waveOut 环形缓冲队列 → 声卡；`game.rs` 播放器类型由
  `AudioPlayer<SilentSink>` 改为 `AudioPlayer<DefaultSink>` 并
  `open_default_sink(48_000, 2)`（主音量 0.8→0.9）。

**关键决策**
- **零第三方依赖**：不引入 rodio，改用 `#[link(name="winmm")]` 的 `waveOut*` 原生 FFI
  （waveOutOpen/PrepareHeader/Write/Unprepare/Close/Reset）。
- 缓冲结构：`BUFFER_COUNT=4` × `FRAMES_PER_BUFFER=2048`（双声道 ≈85ms 队列）；主线程每帧
  tick 写入小块样本（350FPS 时 ~137 帧/帧），回调线程 `WOM_DONE` 归还空闲槽；free 列表用
  `Arc<Mutex<Vec<usize>>>` 保护回调与主线程竞争。
- 失败降级：`waveOutOpen` 失败 → 内部静默模式（不开声但绝不崩溃，日志告警）。

**验证结果**
- 主菜单/战斗中枪声、爆炸、脚步、环境风、音乐均真实输出——用户此前反馈「进游戏一点声音
  都没有」；waveOut 打开成功日志（`waveOut 打开成功 48000Hz/2ch（4 块 x 2048 帧缓冲）`）。
- 无设备平台静默降级，未引入崩溃；`SilentSink` 保留仅测试用。

## 五、128v128 大战场压力模式（NPC 容量扩容）

**做了什么**
- 默认大战场由 **64v64 上调到 128v128**：`main.rs` 注入 `RV3D_STRESS_AI=128`，
  `game.rs` 默认 `stress_sides = 128`（红 128 vs 蓝 127+玩家 = 256 人，`RV3D_STRESS_AI=0/off`
  恢复波次）。意图：以海量 NPC 逼近真人联机压力。
- **NPC 实例容量扩容**：renderer/build 的 NPC 三几何区（盒/圆柱/球）各 1024 段上限提升到
  **2048**（256 人 × 7 段 ≈ 1792，留余量）；`NPC_INSTANCE_BASE`、`EMISSIVE_INSTANCE_BASE`
  与枪模 identity 槽随之整体上移（65536+1+2048 / +6144）。

**关键决策**
- 用「每侧 128 人× 三三制编制」（见第七节）作为压力边界，同时把 NPC 可视化段数上限翻倍，
  保证 256 人不超出三几何区容量。
- 压力规模仍由 `RV3D_STRESS_AI` 可调并 ≥4 才生效（<4 回退默认 128），避免压到测试环境。

**验证结果**
- 128v128 下 NPC 全部有体素可视化（无段数截断），两军互射 + 迫近真人压力的 AI 负载下帧率
  仍可接受；`RV3D_STRESS_AI=0` 恢复波次模式不受影响。

## 六、CPU 拓扑与亲和绑定（含 GetLogicalProcessorInformationEx 步长坑）

**做了什么**
- **Windows 精确拓扑**（`c0a719c` + `25d83a8`）：用 `GetLogicalProcessorInformationEx`
  解析物理核 / CCX(L3) 分组 / 能效等级（0=P 大核 1=E 能效核 2=LE 低功耗核），按
  `SetThreadAffinityMask` 做真实亲和绑核。
- 分组策略：逻辑/渲染同簇（P-core 组 / AMD 主簇=CCX0，共享 L3）；AI/地图生成等后台走
  `ai_pool`（E-core / 次簇=CCX1）；音频等简单低延迟任务走 `audio_set`（LE > E > 第三 CCX >
  次簇 > 主簇）。
- `scene_pool`（P 核/CCD0，近组/交互 AI + 渲染侧场景计算）与 `ai_pool`（E 核/CCD1，远组/
  后台 AI）双池按 CCX 分簇绑定，`RV3D_CPU_PIN=off` 可关，`RV3D_CPU_PIN=0-7,16-23` 覆盖掩码。

**关键决策 / 坑（必记）**
- **FFI 结构体步长必须实测**：`GetLogicalProcessorInformationEx` 的
  `SYSTEM_LOGICAL_PROCESSOR_INFORMATION_EX` 联合体，注释写 40 字节，**实测 sizeof = 48**
  （缓存/核心关系条目均 48B 步长，2026-08-22 实测）。步长算错 → 拓扑全乱（能效等级错位、
  CCX 分组错乱、绑到错误核心）。`25d83a8` 修复此步长后才得到正确的核/超线程/能效拓扑。
- 调试机位（debug-camera）HUD 帧率冻结与拓扑无关，但同 commit 一并修复（见第八节教训）。

**验证结果**
- 修复步长后日志输出正确的 vendor/threads/primary/secondary/e_cores/ccx_groups/efficiency/
  le_set/audio_set；亲和掩码命中预期核心集合；逻辑/渲染与 AI/后台各归其簇，跨簇访问减少。

## 七、人形 AI 指挥体系（三三制 / 逐级汇报 / 司令决策）

**做了什么**
- 新增 `src/engine/ai_command.rs`（未提交）：三三制编制（营→连→排→班→战士，每营 128 人，
  班=3 战士+班长；排=3 班+排长；连=3 排+连长/副官；营=3 连+营部，红蓝各一营 = 128v128）。
- **逐级军情汇报**：战士→班长→排→连→营自下而上汇总为 `CompanyReport`（兵力/质心/接触/击杀）。
- **AI 司令战役决策**：营司令按前线推进度/兵力/伤亡每 0.5s 出 `BattleSituation`，下
  进攻（前推接触线）/ 防御（占线保持，伤亡>40% 转入）/ 侧翼（向敌侧后迂回钳形）/ 重组
  （退连部方向整补）四级命令，逐级下发为班目标点；未接敌战士按班目标编队推进（班长居中、
  战士侧后 3m 楔形），接敌后交还既有逐人战术。
- 连长对班长投掷压制的**指挥权加成**（压制翻倍）并入 `ai_command`；投掷实现在 game.rs。

**关键决策**
- 指挥体系只做**编制/目标/报告**，投掷等具体执行仍在 game.rs（module 边界清晰，方便单测）。
- 大规模下用**分层决策降耦合**：司令只管战役级目标，逐人细粒度交给既有战术 AI，避免
  O(n²) 全图搜索在 256 人下失控。

**验证结果**
- 压力模式下 NPC 按班目标编队推进、接敌后回归战术行为；营级决策按前线态势切换进攻/防御/
  侧翼/重组；班长投掷压制受连长指挥加成后压制效果翻倍（有单元测试覆盖）。

## 八、开发教训（务必记住）

1. **改完必须回归验证，别只看局部画面**：本轮多次出现「渲染改完但整体已坏」——FP 枪模在
   结算态漂浮、调试相机 HUD 帧率冻结、阴影覆盖在高楼城市穿帮。任何视觉/渲染改动都要跑
   冒烟（VUID=0 / kills≥1 / fps≥120 / panics=0）+ 逐相机/逐关卡截图，确认**结算态**不穿帮。
2. **调试机位的窗口遗留会误导视觉判断**：用 `RV3D_CAM` 固定机位或检视模式检查场景时，
   若该机位窗口/相机状态在切回 Playing 后仍残留，会把「机位问题」当成「美术/布局问题」。
   排查时先确认机位已复位到第一人称眼位，再对画面下结论。
3. **FFI 结构体步长必须实测校准**：`GetLogicalProcessorInformationEx` 联合体 40B 注释 vs
   48B 实测即教训。凡直接 `#[repr(C)]` 对接 Windows C 结构体，用 `size_of` 实测并打日志
   校验，否则拓扑/亲和全错且很难排查。
