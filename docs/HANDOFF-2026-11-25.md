## 3. 怎么自证（不要弹窗、不要抢鼠标）

一律 **`RV3D_HEADLESS=1`** 离屏跑：

```bash
# 编辑态：1320+ 帧内实体数与哈希不变
RV3D_GPU=dgpu RV3D_HEADLESS=1 RV3D_HEADLESS_SIZE=320x200 RV3D_AUTOSTART=1 \
RV3D_EXIT_AFTER=10 RV3D_EDIT=1 RV3D_EDIT_PROOF=1 ./target/release/steel-front \
  | grep "mode=Edit"          # 期望：所有行 hash 相同

# 播放态：同一哈希每帧都变（NPC 在动）
... RV3D_EDIT=0 RV3D_MAP=assets/maps/defense_line.toml ... | grep "mode=Play"

# AI 接口闭环（存盘→撤销→读回→再存盘，两文件必须逐字节相同）
RV3D_AIPC=27133 ... &  然后 CMD scene.instantiate / scene.set / gizmo.scale /
                       scene.dump 1 / scene.save / scene.undo / scene.load_into /
                       scene.save / wave.info / wave.spawn 3
```

⚠️ **`RV3D_EDIT_PROOF` 的哈希必须用 `dump_lines`，不能用 `to_toml`** ——
`to_toml` 会跳过只读镜像（NPC），用它算哈希就**看不到 NPC**，
播放态会假装"帧帧相同"。这条踩过一次，判据 `dump_includes_readonly_while_save_skips_them` 钉住了。

## 6. 这一晚最贵的教训（比代码更该继承）

1. **判据会自己失效**，形态至少有五种：
   恒真断言（`.len() >= 0`）、测错对象（提示文字长度当"面板有界"）、
   注释声称"注入会红"但没红、注入**根本没落盘**（缩进差两空格）、
   **判据搜索源码字面量时全局替换会改掉它自己的期望值**。
   ⇒ 工具：`judge_audit.py`（静态）+ `inject_check.py`（真跑注入，先判 `before != after`）。

2. **改了 A 的语义，要回头问"谁靠 A 做测量"**。
   `to_toml` 跳过只读是**正确修改**，却让自证哈希失去对 NPC 的敏感度，而**没有任何东西报警**。

3. **"没跑成"是第三种结局**。0 = 扫过无发现 / 1 = 有发现 / 2 = 根本没扫成。
   工具扫到 0 个输入时必须报 2，不能报"通过"。

4. **中断后第一件事是 `git status`**。被打断的注入会留在源码里（`finally` 没跑到）。

5. **覆盖率不是越高越好**。删掉 6 条无法证实的记账后覆盖率只涨 5，但每一分都站得住。
   孤儿记账（对不上任何声称）与假账等价 —— `judge_audit` 的检查 D 专抓这个。

6. **同形状的块重复出现时，字符串替换会命中错的那一处**。
   要么按行号定位，要么先 `git checkout --` 回滚重做（`app_update.rs` 被替换搞乱过一次）。
