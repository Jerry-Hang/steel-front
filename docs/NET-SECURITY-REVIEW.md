# 联机安全审阅 — steel-front UDP 栈（2026-10-24 第一轮）

范围：`src/net.rs`（协议/编解码/服务器注册/中继）、`src/engine/game/net.rs`（服务端 tick、输入应用）。
方法：源码审阅 + 对本地 server 模式做黑盒探测（本文件只记录结论；给出代码位置便于复核）。

## 发现的问题（按严重度）

| # | 问题 | 位置 | 影响 | 建议 |
|---|---|---|---|---|
| 1 | 无会话令牌/握手认证：Join 只有版本+名字，之后 Input 仅靠源 IP:port | `net.rs:1048`、`game/net.rs:198` | 能伪造源地址的对手可冒充某客户端注入移动/开火；也可伪造 Join 抢名额 | Join 回包带 32 位随机 token；Input 必带并校验 |
| 2 | 无每源限速：`while let Ok(Some(...)) = server.recv()` 每帧无限排空 | `game/net.rs:135` | 单机 UDP flood 可卡死**渲染同线程**主循环 | 每帧最多处理 N 包（如 256）+ 每源 token bucket（如 200 pkt/s） |
| 3 | 中继回复 `OK <addr>` 直接信任为服务器地址 | `net.rs:287-305` | 控制/伪造中继者可把客户端引到恶意服务器（MITM） | 房主公钥/指纹放进 REG，OK 回包含签名；客户端校验 |
| 4 | 名字最长 255 字节、不过滤控制字符且会回显 | `net.rs:604-608` | 若名字上 HUD/日志：换行/控制字符注入、伪造系统消息 | 过滤 `\x00-\x1f`、字符集白名单、长度 ≤24 |
| 5 | 远端移动步长用服务端 `last_dt` 直接乘 | `game/net.rs:350` | 服务端卡顿/flood 时 dt 变大 → 远端瞬移（#2 的下游症状） | `dt.clamp(0.0, 0.05)` |
| 6 | 明文 UDP（无加密/MAC） | 全局 | 同网段可嗅探位置/聊天；配合 #1 可重放 | 对局低敏感可接受；要防则 XChaCha20-Poly1305 + 每包 nonce |

## 建议的验证方式（可当回归判据）

1. 对抗性单测：伪造 token、重放旧 seq、超大 count、NaN/±inf、截断包、多字节垃圾（现有测试覆盖部分）；
2. 黑盒压测：本地 server 模式 + 外部脚本灌 1 万包/秒，观察主循环帧时间与内存；
3. 源地址伪造：需要 raw socket（root）在**本地虚拟网卡**上做，验证 #1；
4. 中继 MITM：本地伪造中继回包，验证客户端是否接受错误地址（#3）。

> 备注：本审阅只针对本仓库自己的联机代码；不包含对第三方目标的测试。
