## 切档说明与已知噪声（2026-10-02，v6）

### 三次迭代，每次都以为对了

- **v3（提交 `a2a8075`）曾断言：「"原文 + 追加更正"的链条完整留在同一档内」——这句是假的。**
  错版留此，更正如下。v3 把每个 `## ` 当原子，实测 **277 个相邻节对里有 164 个（59.2%）被分到
  不同档**，其中一条调查链被切成 5 个档（原 L3834 `character-gun` → L3842 `city-geometry` →
  L3848 `unsorted` → L3854 `engineering` → L3867 `ai-net-audio`）。根因：本文档的 `## ` 同时
  承担"事件标题"和"事件内小标题"两种角色，`改动` / `取证` / `判定` / `症状与根因` / `为什么`
  都不是独立小节。
- **v4 改成"续写标题粘回前一个事件"，但只扫 H2 ⇒ 把 H1 吞进了上一节正文。** 实例：L1713
  `## 📄 文档维护：AGENTS.md 压缩` 之后是 L1721 `# ✅ 未结案 #9 结案：mesh 着色器通过严格
  spirv-val`，再才是 L1723 `## 症状与根因` / L1733 `## 修法 build.rs::strip_workgroup…`——
  那两节属于这个 H1（mesh 着色器），v4 却把它们粘给了 AGENTS.md 那一节。
  v4 还另有一个静默 bug：Python 的 `\u` 转义**只吃 4 位十六进制**，`u'\u1f3af'` 被解析成
  `U+1F3A` + 字母 `f`，所以 emoji 集里所有平面外字符（🎯📊🔍🔧📄🛑🔎🪖）全是垃圾值，
  186 个边界只认出 134 个。**是"打印每个首字符的判定结果"这条自检抓到的**——不自检就会静默发出去。
- **v5 允许 H1 区域内的"事件标记 H2"自成事件**，实测 **186 个里有 118 个与父 H1 不同档**。
  实例：`# ✅ 追了两天的"池子坑"真根因（水平面绕序）` 这一个调查，被 `## 1. 症状与误诊`→
  `city-geometry`、`## 2. 定位链`→`engineering`、`## 4. 修复与判据`→`engineering`、
  `## 5. 教训`→`engineering` 拆成 3 个档。那里的 `1.` `2.` `4.` 是**一份报告的列表项**。
- **v6（本档）＝ H1 区域内不再下切**，只在"日期或轮次指纹不同"时才让 H2 脱离父 H1 自成事件。

### 🔴 最贵的一条教训：**先把整帧拆开，再决定优化哪一半**

此前（含历史记录）一直在优化渲染，而 `cam:` 行给出的事实是：
```
cyc=6484  upd=3889  ren=2594     ← update 60%，render 40%
game: wave=1 enemies=8 phys_us=3241  ai_us=596
```
**一帧 6500µs 里物理一个人占 3270µs，而全场只有 8 个敌人、玩家没动。**
根因是 `resolve_body_pairs` 的 **O(n²)** 双循环（城市约 5 千个静态障碍），
且"静态-静态不解析"的判断写在 `overlaps()` **之后** —— 一次比较都省不掉。

⇒ **任何性能结论之前先量「整帧分解」（`cyc/upd/ren` + `game:` 行的四段）。**
只看 `frame_us`（它只覆盖 `render()`）会把 60% 的时间当成不存在。

## 2026-10-13 第五轮：整帧准备段大扫除（CPU 侧，累计可观）

### 起点：一个没人量过的缺口
```
cyc = upd + ren                        ✅ 自洽
但 ren(21273) − frame_us(19224) ≈ 2000µs
```
`Renderer::render()` 尾部只有 3 行 ⇒ 缺口在 **`GameApp::render()` 包着渲染器的那一段**
（2531→3283，752 行）。于是加了 `[prep-diag]` 细分埋点，逐项量：

```
准备段合计 706~1573µs
  HUD 几何+上传   400~990µs   ← 最大
  + marker        190~570µs
  + NPC 视觉       50~130µs
  + 尸体            1~2µs
```
（`HUD quad 数` 也一并打出来，用于判断该不该动字模。）

### 三刀（每刀都单独实测）

**① `edf4f66` 枪模只在换枪时重建+上传 —— 缺口 2000µs → 911µs（省 ~1100µs）**
`set_first_person_gun_mesh` 原本**每帧**被调用，会把整把枪拷进映射缓冲
（AK-12M = 63283 顶点 × 32B = 2.0MB + 70479 索引 × 4B = 282KB）；
上游 `first_person_gun_mesh()` 还先返回一份**带所有权**的副本 ⇒ 又是 2.3MB。
**⇒ 每帧约 4.6MB 的无效搬运。**
而枪模是**按武器 key 缓存**的、姿态走 `fp_gun_pre` 矩阵 ⇒ 同一把枪下逐帧完全相同。
⇒ 新增 `gun_mesh_uploaded_key: Option<String>`，只在 key 变化时重建+上传；
⚠️ 切到"不显示枪"时**必须清空 key**，否则"隐藏→再显示同一把枪"不会重传、**枪会不见**。

**② `96692db` HUD 顶点直写映射缓冲（上传项 ~380µs → ~290µs）**
`set_hud_quads` 原本每帧 `Vec::with_capacity(count * 6)` + 逐顶点 push + memcpy。
而 HUD 顶点缓冲**本来就是映射内存**、按在飞帧槽位分开 ⇒ 直接写省掉分配与拷贝。
⚠️ **分配不是主因** —— 改完仍有 ~290µs，说明写入本身是（quad 数是几千级）。

**③ `197cc0f` 字模连续像素合并 —— HUD quad 数 3147 → 1701（-46%）**
根因：`render_text` **每个点亮的像素一个 quad**，一个 12×12 汉字最多 144 个。
改法：同列内上下连续的点亮像素合并成一条竖条（中文支按行合并横向连续像素）。
**覆盖的像素逐格相同、颜色相同、绘制顺序不变** ⇒ 画面逐像素一致。
**没有做纹理图集**：那要新增纹理+采样器+着色器分支+可能的管线，而本仓对管线/描述符
改动有明确红线，且字体源文件未入库、字模表不能重建。合并是纯几何操作，风险与收益比完全不同。

**测试判据也跟着改了**（这是本轮另一处值得记的）：
原来两条测试断言 `out.len() == 置位像素数` —— **把「每像素一个 quad」这个实现细节固化成了契约**，
于是合并一来就撞红，即使画面逐像素不变。改成断言**被覆盖的整数格集合 == 字形置位像素集合**
（比旧断言更强：直接钉住渲染出来的像素）；并**新增** `render_text_merges_vertical_runs`
断言竖笔画字形的 quad 数**严格小于**置位像素数 —— 否则把代码改回逐像素也全绿。

### 本轮可下的结论
* `cull_us`：**1132 → ~600µs（-47%）**（线程池 + 实例数，见第三轮）
* 准备段：**~2000µs → ~900µs 量级**（枪模占大头）
* HUD quad：**3147 → 1701（-46%）**
* ⚠️ **fps 一直没能作为验收口径** —— 手机反复进入快充降频（`present_us` 在
  985 / 17776 / 34767 之间跳，fps 42→24），**同一个二进制能差 3 倍**。
  **⇒ 本轮所有结论都用的是"同口径、可复现的 CPU 侧微秒数"，不是 fps。**
  要看 fps 净收益，得等手机不充电、温度落下来再跑一次完整 A/B。

### 2026-10-22（续4）：RV3D_HEADLESS —— 无窗口离屏取证，彻底解决"霸屏"

用户两次反馈"还是在霸屏"：本机 Wayland 下 winit `with_visible(false)` 不保证窗口不被 map。
解法 = **离屏渲染**：`RV3D_HEADLESS=1` 时**不创建交换链、不 present**，只创建 3 张离屏
COLOR_ATTACHMENT|TRANSFER_SRC 图像充当"交换链图像"（主 pass 仍渲进场景图、照旧 blit 过去），
窗口从不 attach buffer ⇒ xdg-shell 不映射 = **零上屏、零抢焦点**；结果走既有截图读回写 PNG。

- 关键接线：`init_headless_target`（swapchain.rs）、acquire 轮转 / submit 不参与信号量 /
  present 变成 `Ok(false)`（frame.rs）、离屏图像的落点布局 = `TRANSFER_SRC_OPTIMAL`
  （`swapchain_final_layout`，record ③ 与截图读回两处同源）、Drop 里**先 framebuffer 后
  ImageView/Image**（顺序反了实测退出段错误）。
- 首次实测：`RV3D_HEADLESS=1 RV3D_SHOT_AT=3 RV3D_EXIT_AFTER=8` ⇒ PNG 1280×720、exit=0、295fps、
  0 panic/0 device lost；`RV3D_HEADLESS_SIZE` 控制离屏分辨率。
- 判据：`parse_headless_size_clamps_and_falls_back` + `final_layout_matches_present_mode`。
- 顺带经验：无头模式下窗口尺寸与离屏分辨率本来就不同，**必须跳过"窗口尺寸 vs 交换链尺寸"自检重建**
  （否则每帧重建；首版实测刷了 18 次日志）。
- 验收：0 警告 / **833 passed + 4 ignored** / CJK 门 OK / 白名单 OK。

### 2026-10-22（续7）：地面"近景糊"的三次实验——**证伪**

现象：街面近景（尤其画面下半）地面糊成一片、只剩低频色调。

1. **放宽纹理掠射淡出** `gt_fade` 阈值（0.10/0.30 → 0.20/0.60 → 0.35/0.90），三档 SPV 同机位 A/B：
   近景 Laplacian **1.573 → 1.395 → 1.394**（反而降），近景 std 12.04→12.58→12.59；
   地平线条纹 1.608 → 1.621 → **1.958**（0.35/0.90 明显变差）⇒ **放宽阈值不能改善糊，还会带坏远景**，
   实验**回退**，保留 0.10/0.30。
2. 检查烘焙分辨率：地面纹理已经是 **1024² 覆盖 512m（0.5m/纹素）**，不是 512² ⇒ 提高分辨率不是主要杠杆。
3. 结论（下一步方向）：糊的真因是**掠射角下隐式 mip 取到低层 + 无各向异性过滤**。可走的两条：
   ① 世界空间细节层用**较小轴向导数**做 LOD（各向异性近似，长轴方向用拉伸代替消失）；
   ② 给地面加 2–3 tap 的沿长轴多点采样（成本可控）。两者都能在无头模式下量化（近景 Laplacian + 条纹指标）。

### 2026-10-22（续8）：地面各向异性近似 —— 近景细节翻倍、条纹反降

- 做法（片元，零新增资源）：把每像素世界足迹拆成**两个屏幕轴向**的 xz 长度：
  `minor`（垂直视线，决定还能保住多细的纹理）/ `major`（沿视线拉伸，混叠来源）：
  - 宏观地面纹理改**显式 LOD**：`lvl = log2(max(minor/0.5m, 1))`；
  - 淡出闸门改看 **major** + **拉伸比**（`stretch = major/minor`，>4–10 时退平）；
  - 细节层（7.8mm/纹素）闸门改用 **minor**，沿拉伸方向"拉长"而不是整块消失。
- 三档阈值 A/B（无头、同机位、只换 SPV）：

  | 当前（改动前） | 1.573 | 12.04 | 1.608 |
  | aniso 原始 | 3.045 | 12.66 | 2.262（回退） |
  | **v2（采用）** | **3.149** | **14.37** | **1.572** |
  | v1 | 3.126 | 11.87 | 1.658 |
  | v3 | 3.167 | 11.78 | 1.640 |
- v2 阈值：`gt_fade` 看 major（0.3/1.0）+ 拉伸比（4/10）、细节层 minor（0.10/0.30）。
  **近景高频 +100%、条纹 −2%**（比改动前更干净）；目视近景增加细颗粒，无拉伸条纹伪影。
- 代价与边界：沿长轴仍是"拉伸纹理"而非真各向异性过滤；真正的 SSAO/各向异性仍列为后续专项。

### 2026-10-22（续11）：砖缝"糊"真因修复 —— marker_skin 倒角过宽（+9.1% 墙面细节）

### 2026-10-24（续34）：修 S6（High）——"服务器已满"不再永久锁死客户端
