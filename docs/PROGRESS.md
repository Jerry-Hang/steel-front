## 切档说明与已知噪声（2026-10-02）

- **移动单位 = 一整节 `## `**，逐字搬运；任何一节都没被从中间切开，所以代码围栏与
  "原文 + 追加更正"的链条完整留在同一档内。历史约定不变：**错版保留 + 追加更正**。
- ⚠️ **本块初稿在这里写过一句错话**，留作方法教训。原文：「行尾已核：HEAD 原文与切档后
  均为纯 LF（`target/eol.py`）⇒ 搬运是字节级的」。该检查**无效**——它拿磁盘文件去比
  `git show HEAD:` 的输出，而本仓 `core.autocrlf=true`，blob 侧永远已归一化为 LF，
  这个对照**看不见 CRLF→LF 翻转**。实测工作区常规是 CRLF（`src/*.rs`、`AGENTS.md`、
  `README.md` 全 CRLF，见 `target/eol2.py`），切档脚本把 8 个 md 写成了 LF——`git add`
  的警告正是这件事。⇒ 已把工作区行尾改回 CRLF；blob 侧不受影响（add 时归一化），
  提交内容无行尾噪声。
  **可复用的规则：验"逐字"必须 blob↔blob 或 disk↔disk，跨这两个平面比行尾等于没比。**
- **归属由关键词加权打分决定（标题权重 4、正文前 600 字权重 1），不是语义判断。**
  ⇒ 主题档只当**导航**用，**不要**把"某节在哪个档里"当成该节的性质认定。

  ⇒ 修正方式：直接改下面索引里的主题档列 + 移动该节，**不必重跑切档脚本**。
- **`docs/progress/unsorted.md`（12 节 / 17.1 KB）是分类器无信号的兜底档，需要人工归档。**

  `丢失节 0 / 跨文件重复 0 / 凭空标题 0`，且行账 `119 + 14280 = 14399` 与 HEAD 完全相等。
