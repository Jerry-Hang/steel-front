## 三、士兵 GLB 接入（用户 #1 抱怨的正面解决）

**四轮才收敛，每轮都把问题缩小一点：**

1. mesh 路径**结构上做不到** —— `build.rs::MeshOutput` 每 workgroup 上限 **50 顶点 / 96 图元**，
   而 `soldier.glb` 是 1082/540
2. 枪模证明了另一条路：**`cmd_draw_indexed` 的实例数是自由参数**
3. **连管线都不用新建** —— `self.pipeline` 就是传统 VERTEX 管线（depth 开、无条件创建），
   道具早就在用它
4. **品红探针**逼出最后一个真相：**GLB 与 18 段箱体一直在同时画**

**踩过的三个坑（都已修）：**

- **每帧重复上传** ⇒ 每帧泄漏一套 GPU 缓冲（日志一段里 3+ 次"已上传"）⇒ 加幂等守卫
- **每帧从磁盘重读 GLB**（12 秒内 **1277 次**读盘 + 解析）⇒ 加 `OnceLock` 缓存
- **`set_soldier_mesh` 的调用位置**：放错过两次 —— 先放在 `set_dead_bodies` 之后（第一帧读到 0），
  后放在 `MainWindow::render()` 的某个状态分支里（`RV3D_NPC_CAM` 路径到不了）⇒
  **最终移到 `Renderer::new` 之后，结构上不可能被跳过**

**成品**：`soldier.glb` 走实例化（每 NPC 1 个实例），阵营色 = 取向白靠拢 35% 的队色 ×
`tint.w = 6.0`（Authored 标记），步态用实例矩阵做（起伏 ±4cm + 前后倾 ±3° + 开火后坐），
尸体用同一条路（绕原点转 −90° 平躺）。取证：`screenshots/final_b.png` / `team_b.png`。

## 四、阴影：两处缺口（未结案 #14 结案）
