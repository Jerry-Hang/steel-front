# Android 内部渲染分辨率档 —— 规格与改动点

> 2026-10-11 由用户指定档位。**本文只记规格与落点，不含"已完成"的声称。**

## 规格（用户 2026-10-11 修订版）

> 质量(2400*1080)*83.4%, 平衡(2400*1080)*66.8%, 性能(2400*1080)*50%

| 档 | 用户写的 | **实际是** | 本机（2400×1080）实得 |
|---|---|---|---|
| **质量** | 83.4% | **5/6 = 83.33%** | **2000×900** |
| **平衡** | 66.8% | **2/3 = 66.67%** | **1600×720** ← 实测 43~46 fps 那档 |
| **性能** | 50% | **1/2** | **1200×540** ← 实测 61~67 fps 那档 |

🔴 **必须用整数分数实现，不能用百分比**：百分比是那几个分数的四舍五入，
直接乘会得到 **2002×901** 这种**奇数**（升采样的半纹素偏移不对称，部分 GPU 操作也要求偶数）。
用分数则三个档全部落在**干净偶数**上 —— 见 §改动点 #2 的 `RenderTier::ratio()`。

> 修订前那版规格（75% / 50% / 固定 1200×540）已作废：那版里「平衡」与「性能」会落到**同一个尺寸**。
> 现版本三档互不相同、且「平衡」「性能」正好命中已实测过的 1600×720 / 1200×540 两档。

## 为什么值得做（实测依据，非推测）

`docs/progress/android.md` 与 `6b80f92` 的实测：

| 分辨率 | 像素 | fps |
|---|---|---|
| 2400×1080 | 2.59M | 23~24 |
| 1600×720 | 1.15M | 43~46 |
| **1200×540** | **0.65M** | **61~67** |

⇒ **帧率随像素数单调上升**，是**填充率/片元成本主导**，不是 CPU、不是调度、不是合成器。
⇒ 降内部分辨率是当前**最大的单一杠杆**（1200×540 相对 1080p 是 **+165%**）。

且命中本仓既有判据：`docs/DLSS-evaluation.md:62` 的**判据 A**
（内部分辨率降到 1/4 面积而 fps +>40%）—— 该判据在 5060 上不成立、**在 Adreno 810 上成立**
（23 → 61~67）。这也正好讲圆「为什么不接 DLSS 却该做这个」。

## 为什么不能只改 swapchain 尺寸

swapchain 尺寸 = surface 尺寸，由系统决定（`currentExtent`）。**内部分辨率必须是引擎自己的概念**：
主 pass 渲到一张**低分辨率离屏图**，再升采样到交换链；而 **HUD 与菜单保持设备分辨率**
（超分伪影在 2D UI 上最明显 —— 这条是 Snapdragon GSR 官方文档明确写的，
而本仓 HUD 本来就走独立 overlay pass，**架构上已经满足**）。

## 改动点清单（**先 grep 确认符号还在**，行号可能已漂移）

| # | 位置 | 改什么 |
|---|---|---|
| 1 | `renderer.rs` 字段区 | 新增 `render_extent: vk::Extent2D`（内部渲染尺寸） |
| 2 | `helpers.rs` | `enum RenderTier { Quality, Balanced, Performance }` + `RenderTier::ratio() -> (u32,u32)` 返回 `(5,6)/(2,3)/(1,2)`（**比例只此一处定义**）+ 纯函数 `render_extent_choice(w,h,tier) -> (u32,u32)`：按分数缩放后**向下取偶**，并夹到 320×180 下限（小窗口别退化成 0） |
| 3 | `device.rs` init | 初值 + 建低分辨率离屏图（颜色 + 深度，格式与主 pass 附件一致） |
| 4 | `pipelines.rs` | 主 pass 的帧缓冲指向离屏图；`render_pass` 的 `finalLayout` 从 `PRESENT_SRC_KHR` 改成 `SHADER_READ_ONLY_OPTIMAL` |
| 5 | `pipelines.rs` | 新增升采样管线（全屏三角 + `textureSample` LINEAR，输出到交换链） |
| 6 | `swapchain.rs` | 交换链重建时**同步重建离屏图**（尺寸取 `render_extent`，不取 surface） |
| 7 | `record.rs` | 主 pass 之后、磨砂玻璃 blit（`:790`）之前插一趟升采样；**PT 分支跳过** |
| 8 | `record.rs` | `hud_has_glass` 的条件改成 `hud_has_glass \|\| render_scale != 1.0`（否则 HUD 会被一起超分）|
| 9 | `drop.rs` | 销毁离屏图 |
| 10 | `syscfg` | 开关 `RV3D_RENDER_SCALE`（→ Android `setprop debug.sf.render_scale`），**不重编 APK 就能扫档** |

## 验证（照本仓规矩，缺一不可）

1. **`RV3D_VALIDATION=1` 跑一轮** —— 改 pipeline/描述符/布局必须先过验证层
2. **交换链重建路径**：改分辨率 + 转屏，看是否重建离屏图（判据 = 没有 VUID、没有 device lost）
3. **HUD 不进超分**：截同机位图，HUD 文字边缘应**保持设备分辨率锐利**
4. **A/B 量 fps**：每个档位用**同会话交替**测（教训 45：正对照臂 + n≥5 + 中位差）
5. **画质**：与全分辨率同机位 `png_diff`，给差异占比 + **包围盒**（教训 28）

## 明确不做

- **SGSR2**（时域超分）：要运动矢量 + 抖动 + 深度采样路径，即 `docs/DLSS-evaluation.md:37-41`
  那份清单，本仓 `rg motion_vector src/` 零命中。
- **SGSR1**：先做本档位，**量出真实收益再决定要不要接**（顺序不能反 —— 先把免费的采样数/像素数砍到位）。
