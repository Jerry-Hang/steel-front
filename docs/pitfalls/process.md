# 流程与协作 —— 误区与陷阱（8 条）

> 改完没跑、只改一侧、旧结论没删、备份/回滚做错
>
> 返回 [`docs/pitfalls.md`](../pitfalls.md)（总索引与全局综述）。
> 每条格式：**症状 → 根因 → 教训 → 类别**。根因里保留了「当时以为是什么」——那是最值钱的部分。

## 流1. 主路径与回退路径长期不同源：唯一在跑的 legacy 路径完全没有深度遮挡

- **症状**：楼与楼只按绘制顺序互相穿透（"建模一塌糊涂"的另一半原因）；同一份实例在 mesh 路径上材质不同（弹孔方片被叠上一层窗带，看着像"贴上去的小面板"而不是孔）；mesh 路径的圆柱盖绕序与 CPU 相反；mesh 的 `is_gun` 上界越界让爆炸/手雷/粒子被强制画最前（深度 0.5 污染）。（be09664, 2026-09-04；5b716ef, 2026-09-15；1fbb338, 2026-09-19；61da2d7, 2026-08-16）
- **根因**：主管线 `depth_test_enable` 一直是 false 而 mesh 管线是 true——因为第一人称枪模需要"恒可见"，整个世界就陪着它放弃了遮挡（当时把画面问题全归给几何，不够）；mesh 路径没实现 `vs_main` 从 09-13 起就有的 Authored 编码（`tint.w ∈ (5.5,6.5) ⇒ flat_flag=1.25`，让片元跳过四条会采样 UV 的程序化效果）；`INDICES` 里立方体顶/底面与 mesh 圆柱盖按相反约定绕序；`is_gun` 判定没写 `< EMISSIVE_INSTANCE_BASE` 上界。
- **教训**：凡"两条路径/两套模板"共享的语义（深度状态、材质编码、绕序、槽位边界）都要有单一真源 + 一条"两条路径同约定"的判据（`horizontal_winding_tests` 的 mesh 源码文本比对是范例）；特殊需求（枪模恒可见）只给它自己一条管线、且**不写深度**（否则枪模会把自身深度留下、之后的 HUD/粒子反被挡住），并在销毁 shader module 之前创建；改共享计算要双模式验证（第一人称 + `RV3D_INSPECT=1`）。
- **来源模块**：渲染管线

## 流2. D11 窗帘墙带越修越糟：薄盒掠射角前后脸落在同一像素，而屏幕上的塔根本不是那个生成器产的

- **症状**：塔身窗带读出"悬挑鳍"并投出错位阴影；把带子从外挑 24cm 收到 4cm、半宽收到 7.4 后，放大看仍像层板、还多出 V 形干涉；改成在片元里按世界 Y 画窗带后，重建截图**依旧一点没变**。
- **根因**：两层——① 薄盒在掠射角下自己的前脸和后脸落在同一像素，**把带子做薄是错误方向**（正确做法是把窗带画进立面/片元，而不是叠独立几何）；② 更关键的是"屏幕上的塔不代表 `office_tower` 产的"：重建后画面完全不变说明改的生成器不是发源者，只能先 grep 特征色 `GLASS_BLUE` 找全部发射者再动手（该轮结论是 NOT ACCEPTED）。
- **教训**：改一个可见缺陷前先确认"屏幕上那个东西是谁生成的"；改完画面**完全没变**是"改错对象"的判据，不是"改动无效"；掠射角下的几何自遮挡要靠"埋进墙体 / 做进材质"解决，不靠调厚度。
- **来源模块**：城市与几何

## 流3. 再生 → 焊接是两步，漏一步就拿到 4.5 倍顶点量的资产

- **症状**：`gen_props.py --only` 再生后没跟 `weld_props`，拿到的是未焊接的 4.5x 体积——`f3ca834` 的 car_wreck 就漏了（13304→43412B，976 顶点未焊，一笔 3.3x 顶点债），直到后来追账才发现。
- **根因**：生成器只管产出、焊接是独立工具，两者之间没有强制串联；这类流程债不会自己报错——GLB 照样能加载、能渲染，只是顶点数翻几倍（而顶点是本仓唯一的美术预算杠杆）。
- **教训**：流程定死为"再生 → 焊接 → preview 目视 → 测试 → 同 commit"，并把顶点数当验收量（976→324 顶点、包围盒不变、契约测试绿）；埋没/浮空类扫描器（`float_scan`）要当常规闸门跑，而不是等出事后才追。
- **来源模块**：城市与几何

## 流4. 方向类改动：在 WSL2 上从未验证过，真机第一次跑就整轴反向

- **症状**：Windows 原生真机首次跑出"右移鼠标视角左转"；另一轮用户反馈"视角像倒立"；垂直轴的取反当天又被撤销回标准 FPS。
- **根因**：水平轴的符号在"WSL2 输入不可用"的阶段从未被真实输入路径验证过，属于没被覆盖的假设，换个平台就暴露；垂直轴则在"用户反馈像倒立"与"标准 FPS 约定（下移=低头）"之间来回改，两次都同步改测试 ⇒ 测试只是在追认当时的实现，不构成独立判据。
- **教训**：方向/符号这类无法自证的约定必须靠**一次真机最小实验**钉死（拿一个已知在/不在视野里的物体验一次朝向），并把用户最终确认的语义写进测试名与注释；改方向的提交要么给实机取证，要么明写"未验证"，别把平台差异留成下一个人重新发现的东西。
- **来源模块**：输入与交互

## 流5. 把 `pub` 的索引字段当索引用裸下标 ⇒ 崩溃点藏在"当前不可达"后面

- **症状**：`RESOLUTIONS[i]` / `RESOLUTION_LABELS[i]` / `QUALITY_LABELS[i]` 三处裸下标，而设置面板**每帧绘制**，越界即 `index out of bounds` 直接崩（`the len is 5 but the index is 200`，ui.rs:1479）。
- **根因**：查表处依赖"别人代码里的前置条件"（`main.rs` 用 `RESOLUTIONS.iter().position(..).unwrap_or(0)` 赋值），而这两个字段是 `pub`；一旦新增档位或从配置/网络写入，前置条件当场失效。当时它确实不可达，所以测试一路绿。
- **教训**："当前不可达"不是安全证明，而是"前置条件住在别人代码里"；`pub` 字段的所有消费者都必须自己兜底（`get(..).copied().unwrap_or(第 0 档)`，合法索引下行为完全不变）；这类修复要能演示"改前会红"。
- **来源模块**：输入与交互

## 流6. 字模资产不可追溯：专有字体 + 仓里没有生成器 + 源字体不在仓

- **症状**：点阵来自 SimSun（专有字体，禁止再分发）；仓里**没有**生成器（来源不可追溯）；生成物头点名的 `noto-sc-subset.otf`（8.3 MB）也不在仓里（`build/` 忽略）⇒ 别人拿不到、无从复现。旧表还带 92.6% 死数据：21486 条 / 2.26MB 里 19906 条无人引用，实际只用 1580 个码点（167KB）。
- **根因**：资产是"一次性烘出来的产物"入库，而生成链（字体来源 + 脚本 + 码点清单 + 许可证）没有被一起收口；许可证问题直到专门审计才暴露。
- **教训**：任何烘焙资产都要连**来源 + 可复现脚本 + 许可证**一起入库（换成 Noto Sans SC / SIL OFL 1.1，新增 `tools/extract_cjk_glyphs.py` + `--scan` 码点清单 + 字模标定脚本），并在生成物模板里写清"怎么拿到字体、哪一步不需要字体"；死数据按"源码真实引用"裁剪，别把无人引用的表留在仓里。
- **来源模块**：输入与交互

## 流7. 连发两条逐行重复的路径，没调用方的那条还带着一句说谎的注释

- **症状**：`fire_burst` 与 `fire_burst_player` 是两份逐行重复的函数体（只差 `fire_shot` 的 `from_player` 实参），而前者**没有任何调用方**、靠 `#[allow(dead_code)]` 压着；旧注释写着"AI/网络/测试用三连发"，照它去找调用方会白找一轮（编译器判定 0 引用）。同时玩家连发路径**零测试覆盖**。
- **根因**：复制粘贴产生的孪生实现 + 注释与代码脱节：`#[allow(dead_code)]` 把"没接线"这件事压成了静默状态，而注释给出的三个调用方一个都不存在。
- **教训**：看到 dead code 只用编译器判据回答"它为什么没被接线"，别信注释；把重复收成一个实现（`fire_burst(from_player)` + 一行薄入口），**能删掉那条 `#[allow]` 本身就是"没有重复"的证明**；顺手补上此前没覆盖的路径，红证用"把循环次数改成 rounds−1 ⇒ 立刻红（left 2 / right 3）"。
- **来源模块**：游戏逻辑

## 流8. 看门狗把用户**手动启动**的游戏当卡死杀掉："缺少心跳"被当成"心跳过期"

- **症状**：上一版看门狗只判"游戏活着 + 心跳过期"，而用户自己手动启动游戏时**根本没有心跳文件**，那个判据恒为"过期" ⇒ 看门狗在启动约 30 秒后把用户的游戏杀掉（实测：手动启动、确认无心跳文件，用 `-StaleSec 10` 的看门狗跑 40 秒，旧写法会在第 10 秒杀掉它）。
- **根因**：把"没有输入"读成了"输入表明异常"；正确语义是"有一次 harness 运行**认领**过这个游戏"（心跳文件存在）**且**已过期，二者同时成立才允许动手。
- **教训**：看护类脚本在"缺少状态文件"时必须什么都不做（fail-safe，不是 fail-kill），认领与释放成对（`pm_play.ps1` 退出时删心跳文件）；按"启动后睡 N 秒来 arm"这类设计当天已出过两次，这次是同一思路的第三种表现形式——看到重复形状就改设计，别只改这一处。
- **来源模块**：工具与闸门
